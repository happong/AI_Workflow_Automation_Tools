#  웹툴 포털

스펙 문서(`nodejs_tool_portal_spec.md`)에 따라 구현한 카드형 웹툴 포털입니다.

## 실행 방법

```bash
npm install
npm start
```

기본 포트는 `9000`이며, 환경변수 `PORT`로 변경 가능합니다.

```bash
PORT=8090 npm start
```

`0.0.0.0`에 바인딩되어 있어 같은 네트워크의 다른 사람도
`http://<이 PC의 사내 IP>:9000` 으로 접근할 수 있습니다.
(단, 사내 방화벽/네트워크 정책에 따라 실제 접근 가능 여부는 달라질 수 있습니다 —
이 부분은 스펙 5번 항목대로 아직 확인되지 않았습니다.)

## 도구 목록 채우기

두 가지 방법이 있습니다:

1. **화면에서 추가 (권장)**: 우측 상단 "+ 도구 추가" 버튼을 눌러 이름/URL/설명을
   입력하면 바로 저장되고 카드가 나타납니다.
2. **직접 편집**: `data/tools.json`을 텍스트 에디터로 열어 직접 추가할 수도
   있습니다. `data/tools.example.json` 형식을 참고하세요.

```json
[
  { "name": "실제 도구 이름", "url": "http://localhostUIP:포트", "description": "한 줄 설명" }
]
```

두 방법 모두 서버 재시작이 필요 없습니다.

## 로그인 (화이트리스트 방식)

비밀번호 없이 계정 ID만으로 로그인합니다. `data/whitelist.json`에 등록된
ID만 로그인할 수 있습니다.

```json
["내ID", "다른팀원계정ID"]
```

팀원을 추가하려면 이 파일에 계정 ID 문자열만 추가하면 됩니다 (서버 재시작 불필요).

로그인은 **도구 추가**와 카드 순서를 드래그로 바꾸고 **개인별로** 저장하기
위한 용도입니다. 로그인하지 않아도 목록 조회 / 미리보기 / 온라인 상태
확인은 그대로 사용할 수 있습니다.

## 드래그앤드롭 정렬

- 로그인한 상태에서만 카드를 드래그해서 순서를 바꿀 수 있습니다.
- 순서를 바꾸면 즉시 저장되며, **로그인한 계정별로 따로 저장**됩니다
  (`data/user-orders.json`). 즉 A가 순서를 바꿔도 B가 보는 순서(또는 로그인
  안 한 사람이 보는 기본 순서)에는 영향이 없습니다.
- 로그인하지 않은 상태에서는 `data/tools.json`에 저장된 원래 순서 그대로 보입니다.

## 주의사항(⚠️) 표시

AI로 만든 웹툴 특성상 "이것만은 기억해야 하는" 운영 포인트가 있을 수
있어서(예: 공용 P4V 계정 비밀번호를 바꾸면 이 머신에서도 갱신해야 함),
도구 추가 시 "주의사항" 항목을 선택적으로 입력할 수 있습니다.

- 도구 추가 모달에서 "⚠️ 주의사항 (선택)"란에 적으면 카드에 노란색 박스로
  눈에 띄게 표시됩니다.
- 비워두면 아무것도 표시되지 않습니다 (기존 도구들도 이 필드 없이 그대로
  동작합니다).
- 여러 줄로 적어도 줄바꿈이 그대로 유지됩니다.
- 나중에 값을 수정하려면 로그인 후 카드의 "수정" 버튼을 누르면 됩니다
  (이름/설명/주의사항 변경 가능, URL은 도구 식별 기준이라 화면에서는
  바꿀 수 없고 잠겨 있습니다 — URL 자체를 바꾸려면 `data/tools.json`을
  직접 편집하세요).

## 온라인/오프라인 상태 표시

카드마다 초록/빨강 점으로 온라인/오프라인 여부를 표시합니다.

- **방식**: 각 도구의 URL에서 host:port를 뽑아 TCP 연결을 시도합니다
  (2초 타임아웃). 진짜 ICMP ping이 아니라 "해당 포트가 열려서 연결
  가능한지" 확인하는 방식입니다 — 웹 서비스처럼 포트를 열어두는 도구라면
  이쪽이 더 실질적인 지표입니다 (방화벽이 ICMP만 막고 포트는 열어둔
  경우가 흔함).
- 페이지 로드 시 자동 확인, 이후 **30초마다 자동 갱신**됩니다.
- 상단바 "↻ 상태 새로고침" 버튼으로 즉시 재확인할 수 있습니다.
- 온라인이면 응답까지 걸린 시간(ms)도 함께 표시됩니다.
- 상태 확인 자체가 실패해도 도구 목록/추가/미리보기 등 다른 기능에는
  영향을 주지 않습니다.

## 알려진 버그 수정 (이전 버전 대비)

- 모달(도구 추가 팝업)이 클릭 없이 항상 떠 있던 문제, 취소 버튼이 동작하지
  않던 문제 — CSS에서 `.modal-backdrop`이 `hidden` 속성보다 우선 적용되던
  게 원인이었고, `:not([hidden])` 선택자로 수정했습니다.
- 주의사항을 입력하지 않은 도구에도 노란색 경고 박스가 빈 채로 항상
  표시되던 문제 — `.card-caution`에 똑같은 CSS 우선순위 버그가 있었고
  동일한 방식으로 수정했습니다.



스펙 3번 항목에서 확인된 사실 그대로 구현했습니다:

- iframe 미리보기는 대상 웹툴이 `X-Frame-Options` 또는
  `Content-Security-Policy: frame-ancestors` 헤더를 설정한 경우 브라우저가
  강제로 차단합니다. 이는 프론트엔드 코드로 우회할 수 없는 브라우저 표준 정책입니다.
- 이 포털은 어떤 웹툴이 해당 헤더를 쓰는지 **자동으로 감지하지 않습니다**
  (신뢰할 수 있는 감지 방법이 없다는 것이 스펙에 명시된 확인 사항입니다).
  카드마다 "미리보기"와 "새 창에서 열기" 버튼을 함께 제공해서,
  미리보기가 빈 화면으로 나오면 바로 새 창으로 전환할 수 있게 했습니다.
- **실제 구현 시 확인 필요**: 각 웹툴( Build Manager, Asset Progress
  Dashboard 등)이 `helmet` 등의 미들웨어로 해당 헤더를 설정하고 있는지는
  이 문서만으로는 알 수 없고, 실제로 브라우저에서 열어봐야 확인됩니다.

## 아직 미결정인 것 (스펙 5번 항목, 그대로 유지)

- 이 포털을 어느 서버/포트에 배포할지 (신규 서버 vs 기존 Node 서버에 라우트 추가)
- 각 웹툴 URL이 사내망 전체에서 접근 가능한지, 특정 서브넷에 한정되는지
- 각 웹툴의 실제 X-Frame-Options / CSP 헤더 값

이 항목들은 코드로 해결할 수 있는 부분이 아니라 실제 사내 환경 확인이
필요한 부분이라 스펙 그대로 남겨뒀습니다.

## 구조

```
-tool-portal/
├── server.js               # Express 서버, 도구/로그인/순서 API 제공
├── package.json
├── data/
│   ├── tools.json           # 실제 도구 목록
│   ├── tools.example.json   # 형식 예시
│   ├── whitelist.json       # 로그인 가능한 계정 ID 목록
│   └── user-orders.json     # 계정별 개인 정렬 순서 (자동 생성/갱신)
└── public/
    ├── index.html
    ├── style.css
    └── app.js
```

## 동작 확인

로컬에서 다음을 curl로 직접 검증했습니다:

- `/api/tools`가 `{tools, accountId}` 형태로 정상 반환
- 도구 추가(`POST /api/tools`)는 이제 로그인 필요 — 비로그인 시도 시 401,
  로그인 후에는 정상 추가되고 유효성 검사(빈 값/잘못된 URL)도 그대로 동작
- 화이트리스트에 없는 계정 로그인 시 403, 있는 계정은 로그인 성공
- 비로그인 상태로 순서 저장 시도 시 401
- 로그인 후 순서 저장 → 해당 계정으로 조회 시 바뀐 순서, 비로그인/다른 계정
  조회 시 원래 순서가 각각 유지되는 것 확인
- 상태 확인(`/api/status`): 열려있는 포트는 `ok:true`, 닫혀있는 포트는
  `ok:false`, 응답 없는 호스트는 2초 타임아웃 후 `ok:false`로 정확히
  판별되는 것을 확인. 여러 도구를 동시에 확인해도 병렬 처리되어 전체
  소요 시간이 가장 느린 항목(2초) 수준에 머무는 것도 확인
- 도구 수정(`PUT /api/tools/:encodedUrl`): 비로그인 401, 로그인 후 이름/
  설명/주의사항 정상 변경, 존재하지 않는 URL은 404로 확인
